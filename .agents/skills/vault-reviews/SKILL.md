# Project reviews

Read `Agent System/system/vault-model.md` for the data contract and `Agent System/system/ownership.md` for boundaries, resolving paths from the vault root.

Determine the requested scope and review date. Read the relevant projects and linked tasks. Assess progress against success criteria and milestones; identify overdue unfinished tasks, unresolved dependencies, missing next actions, and inconsistent states. Describe stale work only when dated evidence or an agreed threshold supports that conclusion; filesystem modification time alone is insufficient.

Create or update the scoped dated review note with evidence links, findings, and prioritized next-action proposals. Distinguish unknown information from confirmed blockers. Do not convert suggestions into assignments or deadlines.

If source-record changes are requested, route task changes to `vault-tasks` and project changes to `vault-projects`, then record the actual results in the review. Report instruction-system gaps to the architect. Return the review path and the decisions that need the user's attention.
